# ChIP-seq pilot peak calling and signal QC

## Scope

This module performs peak calling and signal-level QC for the validated
SINGLE-END H3K4me3 pilot pair:

- IP: SRR20770297
- Input: SRR20770287
- histone mark: H3K4me3
- condition: day 3

The module consumes the hash-validated filtered BAMs generated by filtering
job 10297738. It does not realign reads or repeat duplicate marking.

## Peak-calling strategy

MACS3 3.0.4 is used in SINGLE-END BAM mode.

The source-informed pilot configuration uses:

- IP as treatment;
- matched Input as control;
- narrow-peak mode;
- q-value cutoff 0.01;
- `--keep-dup all`;
- `--scale-to small`;
- `--nomodel --extsize 147`;
- bedGraph generation with `-B`;
- signal-per-million normalization with `--SPMR`.

The fixed 147 bp extension is not an arbitrary pipeline default. The
publication associated with BioProject PRJNA865478 processed these same
ChIP-seq data with MACS2 using `--nomodel --extsize 147`.

An initial MACS3 sensitivity run (SLURM job 10302502) was also performed
with automatic cross-correlation modelling. MACS3 estimated a fragment
length of 127 bp from 80 bp tags but emitted a warning because the
predicted fragment length was smaller than twice the detected tag length.
The same run reported an alternative cross-correlation solution at
459 bp.

For the source-informed validation, the published 147 bp extension is
therefore used while preserving the CHO-specific effective genome size
derived from the reference selected by this pipeline. The original
publication's mouse genome-size shortcut is not propagated.

The BAMs supplied to MACS3 have already had duplicate-marked records
removed by the upstream Picard/filtering module. Therefore duplicate
removal is not repeated by MACS3.

## Effective genome size

The configured value is:

2366634374 bp

This is the nuclear span of the exact CHO reference used for alignment and
filtering, excluding mitochondrial accession NC_007936.1.

It is explicitly treated as an approximation of effective genome size based
on the available nuclear reference span. It is not claimed to be a
mappability-derived effective genome size and is not claimed to exclude all
ambiguous or N-containing sequence.

## Signal tracks

MACS3 `-B --SPMR` generates:

- H3K4me3_day3_treat_pileup.bdg
- H3K4me3_day3_control_lambda.bdg

SPMR normalization is intended for signal visualization and does not replace
the raw-count scaling used internally by MACS3 for significance testing.

## Peak outputs

Expected primary outputs include:

- H3K4me3_day3_peaks.narrowPeak
- H3K4me3_day3_peaks.xls
- H3K4me3_day3_summits.bed
- H3K4me3_day3_treat_pileup.bdg

The workflow also records the MACS3 version and complete MACS3 log.

## FRiP and signal QC

For the IP, FRiP is calculated as:

reads from the filtered IP BAM overlapping at least one called peak
divided by
total reads in the filtered IP BAM.

The Input is evaluated against the same IP-defined peak intervals. This
produces an Input peak-overlap fraction used as a descriptive background
metric.

The workflow additionally reports:

- peak count;
- number of reference sequences containing peaks;
- summed and union peak span;
- fraction of the configured nuclear genome covered by peaks;
- mean and median peak width;
- median MACS3 fold enrichment;
- median -log10(q-value);
- MACS3 fragment size when recoverable from its outputs;
- IP FRiP;
- Input overlap fraction;
- IP/Input overlap ratio.

No universal PASS/FAIL threshold is assigned to FRiP or the IP/Input ratio
at this stage. Signal quality is reported descriptively.

## Reproducibility

The submission wrapper creates an immutable source snapshot and records:

- repository base commit;
- working-tree status;
- source hashes;
- filtering-validation snapshot;
- eligibility evidence;
- peak-calling configuration;
- exact reference FAI;
- generated input plan.

On the compute node, both complete filtered BAM files and CSI indexes are
copied to node-local scratch and SHA-256 verified before peak calling.

Only downstream peak-calling outputs and QC reports are published back to
persistent storage.

## Current limitations

This remains a pilot-specific downstream entry point.

Not yet implemented here:

- automatic ENA-to-peaks integration;
- generalization to all eligible ChIP-seq conditions;
- paired-end peak calling;
- replicate concordance or IDR;
- blacklist filtering;
- mappability-derived effective genome size;
- automatic bigWig production;
- biological annotation of peaks to promoters or genes.

These extensions should follow successful real-data validation of the pilot.
